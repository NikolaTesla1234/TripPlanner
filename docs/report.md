<a name="3-описание-предметной-области"></a>
## 3. Описание предметной области и функциональных требований

Приложение «Планировщик поездок» позволяет зарегистрированному пользователю планировать свои поездки: указывать пункт назначения, даты, бюджет и составлять план поездки по дням.

### Основные сущности:
- **Пользователь (User)** — владелец аккаунта, может создавать и редактировать только свои поездки.
- **Поездка (Trip)** — основная сущность: название, пункт назначения, дата начала, дата окончания, бюджет, описание, количество лайков.
- **Пункт плана (PlanItem)** — мероприятие в рамках поездки с указанием даты, времени и описания.

### Требования к авторизации:
- Регистрация нового пользователя (проверка уникальности логина, минимальная длина логина и пароля — 3 символа).
- Вход и выход из системы.
- Сессия хранится в зашифрованной cookie (JWT).
- Пользователь видит и редактирует только свои поездки (проверка `owner_id`).

### Функциональные требования:
- CRUD-операции над поездками (создание, просмотр, редактирование, удаление).
- Добавление пунктов плана к поездке (с датой и временем).
- Лайк поездки.
- Статистика пользователя (количество поездок, общий и средний бюджет, группировка по направлениям).
- Валидация вводимых данных (формат дат, порядок дат начала и окончания).

<a name="4-проектирование-базы-данных"></a>
## 4. Проектирование базы данных

База данных реализована на SQLite. ORM — SQLAlchemy 2.0.

### Таблицы:

| Таблица | Поля | Описание |
|---------|------|----------|
| `users` | `id` (PK), `username` (unique), `hashed_password` | Аккаунт пользователя |
| `trips` | `id` (PK), `title`, `destination`, `start_date`, `end_date`, `budget`, `description`, `owner_id` (FK → users), `likes` | Поездка |
| `plan_items` | `id` (PK), `title`, `date`, `time`, `description`, `trip_id` (FK → trips) | Пункт плана поездки |

**Связи:**
- Один пользователь — много поездок (`User.trips`, каскадное удаление).
- Одна поездка — много пунктов плана (`Trip.plan_items`, каскадное удаление).

### Миграции
Используется Alembic для версионирования схемы базы данных. При первом запуске таблицы создаются автоматически через `Base.metadata.create_all()`.

<a name="6-реализованный-функционал"></a>
## 6. Реализованный функционал

1. **Регистрация и вход.** Пользователь может зарегистрироваться с уникальным логином и паролем (минимум 3 символа). Пароли хешируются алгоритмом bcrypt. После входа устанавливается JWT-токен в cookie.
2. **Личный кабинет.** Авторизованный пользователь видит только свои поездки. Неавторизованный пользователь перенаправляется на страницу входа.
3. **Создание поездки.** Форма с полями: название, пункт назначения, дата начала, дата окончания, бюджет, описание. Реализована валидация форматов дат и логики (дата начала ≤ дата конца).
4. **Редактирование и удаление поездки.** Доступно только владельцу поездки.
5. **Пункты плана.** К каждой поездке можно добавить несколько пунктов плана с датой, временем и описанием.
6. **Лайки.** Пользователь может поставить лайк поездке (счётчик отображается на странице поездки).
7. **Статистика.** Страница со статистикой: количество поездок, общий бюджет, средний бюджет, количество поездок по направлениям.
8. **API.** JSON-эндпоинты для получения списка пользователей и поездок.

<a name="8-инструкция-по-запуску"></a>
## 8. Инструкция по запуску

### Требования:
- Python 3.10+
- Доступ в интернет для установки пакетов (или локальный кэш pip)

### Шаги запуска:
1. Разархивировать проект в удобную папку.
2. Открыть терминал в папке проекта:
   ```powershell
   cd "C:\Путь\К\Проекту\TripPlanner"
   ```
3. Установить зависимости:
   ```powershell
   python -m pip install -r requirements.txt
   ```
4. Запустить приложение (двойным кликом на `run.bat` или через терминал):
   ```powershell
   python -m uvicorn app.main:app --reload
   ```
5. Открыть в браузере: `http://127.0.0.1:8000`

### Доступные учётные данные:
После первого запуска база создаётся пустой. Пользователь должен зарегистрироваться через форму `/register`.
